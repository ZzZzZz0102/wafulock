隐形锁 + 您的 PMS：集成前必须问清的 8 个问题

2026年7月10日 WAFU B2B 工程团队 隐形锁 PMS 集成 智能锁 B2B OTA 升级 酒店智能锁

本文由 WAFU B2B 工程团队撰写，面向 酒店 / 公寓 / 物业公司采购负责人与系统集成商。WAFU智能（深圳）专注隐形遥控锁 OEM/ODM，2013 年建厂，出口 60+ 国家。

开篇：当三方互相推诿

去年，南欧一家 180 间客房的精品酒店拍板了「无卡化升级」。业主看中隐形锁——门外无锁孔、无需在每扇门更换刷卡读头。集成商报的是 PMS 联动的手机钥匙方案，锁厂发来了带 RF 遥控的 WF-019 级产品。启动会上，三方都在点头。

三个月后，项目停摆。

集成商说：「锁不支持 Opera。」锁厂说：「你们的网关协议栈不对。」PMS 厂商的 API 沙盒从未做过加密凭证下发测试。宾客仍在用塑料房卡入住，60 扇门半配置状态无人认领。法务费用、变更单和口碑损失，全落在合同里没写清「集成责任归属」的中间地带。

这类故事并不罕见。硬件、网络、软件分开采购，默认就会这样。隐形锁还多一个变量：锁体装在门内，选错了，返工成本极高。

解决办法不是再多发几份宣传册，而是在签约前用一份简短的工程问题清单，要求供应商书面作答。

以下是 WAFU 建议每家酒店、多户型公寓和集成商伙伴必问的 8 个问题。我们在 OEM/ODM 项目内部同样使用。您可以发给任何供应商；若发给我们，我们将免费逐条帮您评估。

签约前（Before You Sign）

1. 你们支持哪些通信协议？有没有 API 文档？

为什么要问：「智能锁」不是协议名。433 MHz RF 遥控（基础款 WF-019 隐形遥控锁）与 Wi-Fi 球形锁（WF-Q7，涂鸦 App）或 BLE 把手锁（WF-016）完全是两套逻辑。PMS 不会直连锁端，而是连云平台、中间件或物业网关。若前期没人把 RF → 网关 → REST/Webhook → PMS 这条链路画清楚，问题一定出现在调试阶段，而不是宣传册里。

合格回答应包含： 负责任的工厂会按 SKU 和部署层级列协议，而非「我们什么都有」。WAFU 产品线覆盖 433 MHz RF、2.4 GHz Wi-Fi、蓝牙 / BLE；酒店级 WAFU SMART-LOCK+ 方案采用 SecureMesh™ 网状组网和网关冗余。ODM 项目可更换模块化通信板（Wi-Fi 6E、Zigbee 3.0、NB-IoT、Tuya、Matter-ready 设计），无需重做整把锁体。

对接 PMS 时，请明确要求：

  • WAFU Connect SDK 文档及沙盒环境
  • Webhook / 事件 schema（入住、退房、凭证撤销、低电量）
  • 已在 Oracle Opera、Protel、Fidelio、RMS 等系统上跑通过中间件——而非一张「开放 API」PPT

若供应商拿不出带版本号的 API 文档和测试租户，「轻松对接 PMS」应视为未验证的营销话术。

2. OTA 固件升级谁来操作？失败如何回滚？

为什么要问： OTA 是修漏洞、增 PMS 字段映射的常规手段，也是一次草率批量升级在同一晚「变砖」数百把锁的风险来源——尤其物业内多批次、多固件版本并存时。

合格回答应包含： 要求书面 OTA 策略，不要只听口头「可以远程升级」。WAFU 云端型号支持管理平台 远程固件推送；酒店项目通常采用 分阶段发布（试点楼层 → 全店），配合 签名包 及与当前 PMS 中间件版本的兼容性校验。工厂应明确：

  • 谁点击「部署」（贵司 IT、集成商，还是 WAFU 托管服务）
  • 更新是强制还是按物业可选
  • 单台失败如何回滚或刷 recovery 镜像
  • 网关连通率低于阈值时，OTA 是否自动暂停

我们不要求您相信宣传册上的「失败率」魔法数字——请索要同等规模物业的 现场 rollout 记录。若供应商说不清回滚，不要把生产门锁的 OTA 权限交给它。

3. 有没有成功对接过类似 PMS / 物业系统的案例？

为什么要问： 纸面协议兼容 ≠ 周六下午三点「退房→凭证失效」的端到端时延。您需要的是：有人已在真实酒店或多户型环境里，跑通过「预订事件 → 门权限 → 审计日志」全链路。

合格回答应包含： 案例要具体：PMS 名称、房间数、凭证类型（手机钥匙 / PIN / NFC）、中间件归属。WAFU 可参考：

  • 德国高端连锁酒店 批量部署 WF-019 隐形锁（1000+ 套），PMS 同步临时密码，潮湿走廊 IP65 稳定运行
  • WAFU SMART-LOCK+ 与 Protel 深度集成（如科隆商务酒店约 120 间）、Opera 级系统通过 API/Webhook 联动 Mobile Key
  • 多户型公寓采用 BLE 或 Zigbee 网关，物业方而非锁厂持有租户 App

要求做一次 沙盒回放：创建测试预订 → 凭证出现在锁或手机 → 退房 → 确认撤销。若供应商只给硬件规格书，它卖的是锁，不是门禁系统。

安装中（During Installation）

4. 门厚 35 mm–80 mm 都能装吗？超范围怎么办？

为什么要问： 采购常按「35–80 mm 门厚」统谈，但每个 SKU 有独立机械包络。薄门改造或厚重防火门装错系列，会出现卡顿、误报「电机堵转」或门体损伤。

合格回答应包含： 用游标卡尺在门上、中、下三点测量，取最小值，对照具体型号：

产品线 门厚范围（WAFU 规格） 备注
WF-019 隐形遥控锁 30–70 mm 锁体深度 22 mm；框深 ≥ 22 mm
WF-026 隐藏防盗锁 按订单配置确认 双系统双电机；可选 Wi-Fi 遥控版便于集中管理
WF-F8、WF-Q7、WF-F4 把手/球形锁 35–55 mm 免打孔替换；标准室内门约 3 分钟装完
WF-V2 断桥铝智能锁 30–60 mm 34 mm 超窄机身，适配有框/推拉铝门
H2 高端生物识别锁 窄框铝门 / 商业门型 需现场确认框体几何尺寸

若确有 80 mm 实芯或防火门，勿假设目录款把手锁能装。WAFU 可提供 定制锁舌延伸件 和 ODM 锁体变型——前提是 安装前勘查 已记录门厚，而非安装当天才发现。

5. 网关断网或掉线，锁还能用吗？离线应急方案是什么？

为什么要问： 网络会断。施工挖断网线、ISP 在入住高峰宕机，都发生过。把「必须连云」当作唯一策略，迟早会困住宾客或员工。

合格回答应分三层：

  1. 不依赖网关的本地开锁
    • WF-019：433 MHz RF 遥控独立于酒店局域网（无障碍典型 ≤ 10 m）；视配置保留手动/机械应急。
    • 存储在锁内的 指纹 / 密码 / NFC 离线可用。
    • 超级电容应急（WAFU 隐形双系统设计 5F / 5.4V）在主电池耗尽时可完成 三次完整开锁。
  2. 依赖 PMS 的凭证
    手机钥匙、一次性退房码通常需近期同步。WAFU 中间件可在 PMS 链路中断时切入 本地缓存模式 并告警工程部——前台仍可发 PIN，IT 恢复网关。
  3. 网关架构
    酒店级 SecureMesh™ 采用 多路径路由，单点 AP 失效不会隔离整层。存量改造项目的 Zigbee 3.0 或 BLE 网关应备冗余，中继位置经 RF 现场勘测 验证，而非仅凭平面图估算。

集成商应书面说明：零云端 当天哪些开锁方式可用，哪些须在 24 小时内完成同步。

6. 门框材质（木门 / 金属门 / 防火门）有影响吗？有没有安装限制？

为什么要问： 隐形锁在门扇内部。金属面层、防火芯、玻璃组合会改变腔体深度、射频衰减和螺钉握力。通过住宅空心木门认证的锁，未经项目评估不能直接用于 60 分钟防火门。

合格回答应包含：

  • 木门： 自攻螺钉 + 膨胀胶塞，应对木材收缩（WF-019 部署标准做法）。
  • 钢木复合 / 金属门： 天线布局关键；金属屏蔽可能削弱 Wi-Fi、BLE 或 433 MHz 信号——建议现场勘测。
  • 玻璃门： 需专用夹具；并非所有隐形锁体适用。
  • 防火门： 以当地规范为准。WAFU 隐形锁可保留门外原有五金外观，但 消防合规 属项目认证议题——需消防顾问与锁厂技术函书面确认。

WF-019 工厂规格列明适用 木、金属、玻璃 门；WF-Q7 另支持 不锈钢、铝、铜。「兼容」仍等于「先测量」。

上线后（After Go-Live）

7. 固件出问题谁负责排查？有没有技术支持 SLA？

为什么要问： 交付后，前台找的是总经理，不是深圳工厂。必须有人承担 一线 → 二线 → 原厂工程 升级路径，且响应时间在合同里可执行。

合格回答应包含：

  • 具名支持渠道（中英文工程台）及严重等级定义
  • 远程诊断：锁心跳、RSSI、电量趋势、最近一次 PMS 同步时间戳
  • 备件政策：电机、射频模块、锁体——酒店项目生命周期 5–10 年，此项不可缺
  • 缺陷归属：若 bug 仅在 PMS 中间件 v2.3 后出现，修复可能需集成商与 OEM 联合发版

WAFU B2B 酒店项目通常将 年度软件/服务 OPEX（云平台、安全更新、技术支持）与硬件 CAPEX 分开报价。若集成商转售锁具，须厘清 SLA 在谁名下——固件工单是否由编写 SDK 的同一团队处理。

8. 用户数据存在哪里？谁有权访问？（GDPR / 隐私合规）

为什么要问： 开门日志、手机钥匙号码、生物特征模板在 GDPR 等法规下均属个人数据。作为数据控制者的酒店集团，不能把合规责任外包给云 tenancy 不透明的锁厂。

合格回答应包含：

  • 生物特征模板（H2 / 猫眼系列的指纹、3D 人脸）：WAFU 酒店方案遵循 隐私设计——模板 AES-256 加密后仅存 锁端安全芯片，原始图像不上传。
  • 访问日志与宾客标识：传输加密 TLS 1.3；云存储区域与保留期限须文档化。WAFU SMART-LOCK+ 酒店栈采用 FIPS 140-3 级硬件安全模块。
  • 子处理器：云由谁托管（AWS、Azure、Tuya、私有租户）？
  • 面向 EU/UK 物业的 数据处理协议（DPA） 是否就绪
  • 审计轨迹：谁查看日志、导出报表、签发 override 钥匙

若回答只是「都在 App 里」，不算合格。您需要一张数据流图：锁 → 网关 → 云 → PMS → 员工管理界面。
